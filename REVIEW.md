# Review findings

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `PunchInIn`, `PunchOutIn`, `RegularizeRequest` | Pydantic's default integer parsing accepts values outside the API's integer-only epoch-millisecond contract, including numeric strings and booleans. | Submit `"punched_at": "1783312500000"` or a boolean and verify the request is rejected with 422. | Made timestamp fields strict integers, retaining the range checks and rejecting explicit null values. |
| 2 | `EmployeeIn.shift_end` validation | The equality check did not run when `shift_end` used its default, so `shift_start="18:30"` could create an invalid zero-length shift. | Create an employee with `shift_start="18:30"` and omit `shift_end`. | Enabled validation of the default so equal shift boundaries are rejected. |
| 3 | `regularize` attendance-date check | Compared a punch-in's local calendar date directly with the record date, rejecting valid post-midnight punch-ins for overnight shifts. | Regularize a 22:00-06:00 shift's 03:00 IST punch-in against the prior shift-start date. | Validate with `attendance_day`, which applies the overnight-shift rule. |
| 4 | `regularize` history construction | Switching a punched record to `ABSENT` or `LEAVE` cleared its punch times without including those changed fields in the audit entry. | Regularize a punched record to `LEAVE`; inspect `history[].changes`. | Include each automatically cleared punch time in the history changes. |
| 5 | `regularize` history persistence and `out_record` | History instants and punch-time `from`/`to` values were stored as integers, unlike the BSON datetime representation specified by the data model. | Inspect a newly regularized MongoDB document and compare its nested change values with the API response. | Store history instants as BSON datetimes and convert nested times to epoch milliseconds at the response boundary. |
| 6 | `regularize` optimistic update | A seeded record without a `history` field was treated like one with `history: []`, causing a valid correction to fail its compare-and-set filter. | Regularize a seeded document after removing its optional `history` field. | Match the field as missing when it was absent in the fetched document. |
| 7 | Department summary and trend rounding | MongoDB `$round` uses ties-to-even, but the contract requires half-up rounding. | Use a calculated average or rate exactly halfway between the requested decimal places. | Replaced `$round` with decimal scaling and floor-based half-up rounding in the aggregation expressions. |
| 8 | `health` | Catching every exception could disguise application errors as a MongoDB outage. | Cause a non-PyMongo programming error and observe that it should not become a 503 response. | Limit the 503 conversion to `PyMongoError`. |
| 9 | `out_record` time conversion | Converting datetimes through floating-point `timestamp()` can lose millisecond precision. | Convert a BSON datetime with a non-zero millisecond component and compare the epoch value. | Calculate milliseconds using integer datetime deltas. |
| 10 | `list_attendance`, `explain_endpoint` date filters | Empty date query parameters were silently treated as omitted instead of being validated as invalid dates. | Request `/attendance?date_from=` and verify it returns 422 rather than an unfiltered page. | Check for `None` separately from empty strings before parsing. |
| 11 | `create_indexes`, `department_summary` explain | The monthly summary's unfiltered `joined_on` predicate had no supporting index, producing a collection scan. | Inspect `GET /admin/explain/department_summary?month=...` on the unfiltered query. | Add the `joined_on` index and verify the plan uses `IXSCAN`. |
| 12 | `out_record` | Optional fields omitted by seeded records were also omitted from API responses, although the attendance response schema requires them. | Read an attendance record without `history`, `half_day`, or stored minute totals. | Fill the documented empty-history and zero/false derived defaults when serializing. |
| 13 | `explain_endpoint` | The analytics explain modes explained only their initial filter (or a separate lookup), not the endpoint's actual aggregation. | Compare explain input with each endpoint's filtering, joins, grouping, ranking, and gap filling. | Share each aggregation builder between its endpoint and the explain route. |
| 14 | `explain_endpoint` response serialization | Full explain plans for decimal-based pipelines contain BSON `Decimal128`, which FastAPI's standard encoder cannot serialize and returned 500. | Call the department-summary explain endpoint after using decimal half-up expressions. | Serialize the raw explain document as MongoDB Extended JSON before returning it. |

Reviewed and not identified as defects: the unique (`emp_code`, `date`) index makes punch-in creation race-safe; punch-out uses a conditional update so only one concurrent request closes a record; the department summary starts from employees to include employees with no logs; and the leaderboard applies `$rank` before its cutoff so tied ranks are retained.
